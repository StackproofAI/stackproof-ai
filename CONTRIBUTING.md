# Contributing to STACKPROOF AI

Thank you for your interest in improving STACKPROOF AI.

This repository is the public-facing home for approved project documentation, architecture references, engineering standards, and contributions. Do not submit private client material, credentials, production workflow exports, or confidential implementation details.

## Before contributing

1. Check existing issues and documentation to avoid duplicate work.
2. Open an issue for substantial changes before starting implementation.
3. Explain the problem, proposed change, expected benefit, and any trade-offs.
4. Keep changes focused and document assumptions.

## Contribution expectations

- Prefer correctness, simplicity, reliability, and maintainability.
- Distinguish verified behavior from proposals and untested work.
- Use current official documentation for external APIs and integrations.
- Include acceptance criteria and relevant test evidence for implementation changes.
- Document security, privacy, failure handling, and recovery implications.
- Do not include secrets, personal information, or customer data.

## Pull requests

A useful pull request should include:

- What changed and why.
- Systems and interfaces affected.
- Tests performed and their results.
- Known limitations or untested paths.
- Security and privacy considerations.
- Any required migration or operational steps.

A review or merge is not a production deployment approval. Deployment requires separate verification and authorization.

## Reporting issues

Use the issue templates where available. For security-sensitive reports, follow [SECURITY.md](SECURITY.md) rather than publishing exploit details in a public issue.
